啟動 / 停止 / 查看狀態

# 服務由 systemd 管理（正式版 port 6969），改 code 後要 restart（無 --reload）
sudo systemctl restart pa-manager.service     # 重啟後端
sudo systemctl status  pa-manager.service     # 看狀態/日誌末尾
sudo systemctl is-active pa-manager.service   # 回傳 active

# 確認 port 是否被「正確的 service」佔用（不要有手動殘留 uvicorn）
ss -tlnp | grep 6969     # 應見 python3.12 (pa-manager.service)

# 看即時 log
sudo journalctl -u pa-manager.service -f
注意：若同時有手動殘留的 uvicorn 卡住 6969，記得 kill 掉，只留 service 那一個，否則 port 衝突。

手動試跑（開發 / 試用版 port 8788）

repo 內有 run.sh，用環境變數切 port，正式版與試用版資料目錄已隔離：

# 正式版 6969（資料在 /srv/pa-manager-prod/data）

需求套件：pip install -r requirements.txt（fastapi / uvicorn / paramiko / websockets / requests / bcrypt / pydantic…）

Port 6969 怎麼串到 Ollama

此系統的「AI 功能」全部走本地 Ollama，不需對外 API key。

  • 使用模型：qwen3.8:27b
  • Ollama 位址：主機 localhost:11434（OpenAI 相容 /v1 由 litellm 代理）
  • 涵蓋端點：/api/copilot、/api/machine/{name}/sensors/analyze、/api/machine/{name}/telemetry/analyze、/api/rack/{project}/telemetry/analyze、/api/machine/{name}/diagnose
  • 若 Ollama 掛掉，管理台本體仍正常運作，僅 AI 相關欄位顯示空白。
測試 Ollama：curl http://localhost:11434/api/version；列出模型：ollama list

實際的 LLM 串接組態（來自 settings.json / profiles）

model    : openai/frob/deepseek-v4-flash-0731:latest   (或 qwen3.8:27b / qwen3-vl:32b)
base_url: http://127.0.0.1:11434/v1        # 就是本機 Ollama
api_key : 加密存放（secrets.json，本機 Ollama 實為佔位值）
auth_type: api_key
api_mode : auto　（litellm 自動判斷 OpenAI 相容）
stream   : false　drop_params:true　modify_params:true
reasoning_effort: high　extended_thinking_budget: 200000

模型是「openai/」前綴 + litellm 代理 → 打 Ollama 的 /v1 OpenAI 相容端點。

切換模型 / LLM Profile

  1. 在對話中直接使用「切換 LLM」功能（本設定已開啟 enable_switch_llm_tool）。
    可用 profile：deepseek-v4-fast（現用）／ qwen3.8-27b-new ／ qwen3-vl-32b
  2. 或手動編輯 /root/.openhands/settings.json 的 llm 區塊，改 model 與 base_url，並把 active_profile 指向對應 profile。
  3. 存檔後重啟 OpenHands Agent Server（見下方）使其生效。

OpenHands 相關服務如何啟動 / 重啟

這些是用 uvx/node 啟動的長駐程序（非 systemd）。重啟可對應 PID 處理。

# 目前相關程序（ps 查看）
uvx openhands-agent-server ==1.42.1  → agent-server --host 127.0.0.1 --port 18000
uvx openhands-automation==1.7.1       → uvicorn ... --port 18001
node .../agent-canvas/scripts/ingress.mjs --port 3000
node .../agent-canvas/scripts/static-server.mjs --port 3001
node server.js                        → pa-terminal-bridge (6968)
/usr/local/bin/ollama serve           → Ollama API (11434)

# 查看目前 PID（避免誤殺別的程序，務必用明確關鍵字）
ps aux | grep -E "agent-server|ollama serve" | grep -v grep

# 例：重啟 ollama（需先確認無人在用，會短暫影響 6969 的 AI 與我本身）
sudo systemctl restart ollama   # 若是 systemd 服務；亦可用 ollama stop 再啟動
給管理者：若要重啟 Ollama，會同時影響① Port 6969 的 AI 功能 ② OpenHands 自身對話。請離峰再做，並告知使用者。

  5. OpenHands：curl http://localhost:18000/health 正常；網頁進 :3000。
  6. Port 無衝突：ss -tlnp | grep 6969 只有 pa-manager.service 佔用。
