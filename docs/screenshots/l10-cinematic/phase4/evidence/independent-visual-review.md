# Phase 4 — 獨立、有限範圍的實際畫面審查

日期：2026-10-13。結論：**NOT ACCEPTED — 照片級真實度未達標，不應擴充至完整 L10／L11。**

本次只審查，沒有修改 renderer、光照、相機、材質或模型。審查者直接開啟下列四組共八張瀏覽器 PNG，另以原尺寸重看 After PCB 與 Cooling，閱讀 `docs/L10_PHASE4_REFERENCE_CALIBRATION.md`、`assets/l10-prototype/README.md`，並直接檢視本機官方 Lenovo 內部照片 `artifacts/l10-reference/phase4-lenovo-internal.png`。沒有使用 Blender beauty render 或僅依程式碼推斷外觀。

## 比較條件核對

四組 JSON 的 `scene.camera`（含 eye／target／yaw／elevation／distance／FOV）、`observed.lighting`、progress、canvas 尺寸，Before／After 均逐值相同。八張 PNG 的 SHA-256 均與各自 JSON 一致。After 四組皆為 asset enabled、載入完成、無資產錯誤，HDR environmentReady 為 true；不是載入失敗後的舊模型畫面。

PNG 均為 **3440 × 1440** 完整頁面截圖。WebGL 在既有頁面配置中的實際 canvas 為 **2127 × 1272**，resolution=1；其餘像素是頁面介面。沒有把 canvas 宣稱為 3440 × 1440 的全幅離線渲染。這組差異可以歸於資產／材質管線，沒有透過不同相機或布光放大 After 優勢。

## 四組 Photorealism 評分

分數是此審查者對**可見畫面**的人工估分，不是量測值、使用者驗收或原廠機構認證。不同相機的先前 Phase 3 分數不能直接當成這四組的相同量尺。60–79 表示可辨認工業硬體、仍明顯是 CGI；本次目標是每組至少 90、整體 95，四組全部未達。為避免以局部混合原型推算整個 Cinematic，本報告不給全系統總分。

## 缺陷對應與實際改善

### CPU／GPU 封裝

- 改善：After 可見封裝基板與接觸上蓋分層，小型邊緣被動元件有終端，沒有增加發光裸晶或虛構 socket 槓桿。
- 未通過：兩個 GPU 與 CPU 仍共享通用蓋面語言；小刻字與貼圖沒有提供可核對的封裝構造。僅靠這些畫面無法確定厚度、基板邊界、封裝 footprint 是此代硬體的正確形式。
- 對應：`assets/l10-prototype/layout.json` 的 `packages`；`build.py` 的 package loop、`spreader flange`、`lapped contact surface`；`author_textures.py` 的 `package` 材質組。這些仍明列 visual approximation，正確的 GLB 格式不會提升其證據等級。

### Compute Board

- 改善：板邊、通孔、連接器金屬接點與絕緣外殼有所區分；PCB 貼圖不再覆滿 Before 的裝飾性網格。
- 未通過：After 最顯眼的是板中央與封裝預定區的空白。板上絲印、焊盤、走線與元件彼此的功能關聯不足，近看仍像簡化電子示意板。這不表示應把 Before 的假線路放回去；問題是缺乏可追溯的裸板布局。
- 視覺分解把封裝隱藏後，沒有可讀接合區會削弱觀眾對「板載封裝」的理解。也不能為填空而猜一套 BGA 球陣或 pad map。此處應先補證據，或明確保留為解說性近似。
- 對應：`layout.json` 的 `powerStages`／`passiveBanks`；`build.py` 的 `smd()`、`connector()` 與元件布局迴圈；`author_textures.py` 的 PCB 線路、焊盤及固定粗糙度區。UV 與 normal map 已存在，但畫面不足以證明有真實 PCB 的微尺度表面和布局密度。

### Cooling Assembly

- 改善：單板的暖銅、黑框、銀色螺件及鰭片不再合併成相似方蓋。新外部輪廓是實際 Mesh 改變，不是換一盞燈。
- 未通過：官方照片中的細密周邊、彎曲管段及局部層次，比原型的直線分支臂、矩形台階與規則短齒更複雜。原型仍受既有封裝接觸錨點限制，不能把「受照片啟發」寫成「已精確重建」。銅面缺少可核對的鍍層／加工方向、邊緣反應及粗糙度尺度；在相同光照下仍有色塊模型感。
- 保留的銀色管路、跨板回路、接頭與長管仍來自舊 JavaScript 資產。它們與新銅蓋的接合是兼容性近似，並非此原型驗證完成的完整液冷組件。這四張靜態比較也不能證明內部流向或轉場完全正確。
- 對應：`build.py` 的 cooling cover／fin／retention 幾何與 `author_textures.py` 的 copper／nickel 材質；全局管路仍在 `app/static/js/l10-hardware.js`。

### Complete Hero 與未替換部分

- After **只換左側 Compute Board 及其封裝／局部冷卻件**。右側 Compute Board、CPU/GPU、銀色冷板、全局管路、風扇、前部 I/O／儲存、機殼與 Rack 均未因這張圖而獲得高精度新資產。
- 左銅／右銀、左板較疏／右板較密的差異可以用來審查原型，但不能當成量產整機應有的差異，更不能據此宣稱整個 L10 已通過。
- 前景風扇仍是八個高度相似的黑盒／圓形葉片圖樣，前部大銀罩仍帶有一樣的反射語言。即使左板達到 90，完整 Hero 仍須另一個獨立品質 gate；目前不得擴張去盲目替換。
- 近照中的遠端／前端有部分被原頁面裁切，Hero 保留了完整外形。比較公平，但這組相機不是有標尺的正交機構檢查，也不足以認證細小接觸面的無穿模狀態。

## 缺少的輸入與下一階段門檻

| 缺口 | 所需具體輸入 | 解決的畫面問題 |
| --- | --- | --- |
| 未覆冷板的同版 Compute Board | 可授權的正交及斜角高解析照片，含比例尺、板邊、元件區與封裝邊界；標明同一硬體版本 | 避免猜封裝尺寸、電源分區及稀疏／亂數布局；使 PCB 不只是綠色底板 |
| CPU/GPU 封裝實體形式 | 同版封裝側面／角落／接觸面近照，或可用的公開封裝外形尺寸圖 | 確定蓋面、基板、黏結邊界，而不是再增加通用矩形層 |
| Cold Plate 外部與接觸機構 | 有尺度的頂視、側視、底面、接口和固定點照片，或授權 STEP／機構圖 | 校準銅臂、鰭片節距、固定件、接觸厚度與管路對位；仍不推造內部微流道 |
| 逐零件材質 | 固定白平衡／曝光的多角度、交叉偏光照片或量測 PBR 參考；材質類型與表面製程資訊 | 區分銅／鍍層／焊錫／PCB soldermask／封裝上蓋的真實反射與微尺度 |
| 資產製作能力與校準 | 熟悉工業硬體的建模／材質作者，以證據逐零件校準輪廓、hard edges、UV 尺度、材質反應；需要時建立高低模烘焙 | `build.py` 的可編輯物件與貼圖是有效管線，但不能把 script-assisted primitives 的數量當作高精度證明 |

停止擴張的門檻很明確：先解決裸板與封裝證據缺口，完成**同一左板**的新一版資產，再用這次固定的相機、環境、曝光及解析度重拍四組。CPU/GPU 與 PCB 必須先消除目前退步；Cooling 不得僅換更亮的銅色；未取得資料的部分繼續明列 approximation。只有這個局部原型被實際畫面驗收後，才討論第二片板與 L11。

本階段可以交付可維護的 Blender → UV/PBR → GLB → 既有 WebGL **資產管線原型**，但不能把這等同於「高精度最終硬體資產已驗收」。本報告不要求繼續無限加細節或調燈，也不要求重新製作既有動畫。
