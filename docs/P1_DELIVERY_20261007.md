## 2. Root causes and fixes

### P1-1 — Redfish severity finding loses its snippet (parity)
Root cause: `NodeSession.add(...)` had no `snippet` parameter, but three callers
passed `snippet=`. `collect_redfish` wraps the call in `try/except Exception`, so
the `TypeError` was swallowed into a generic `REDFISH_UNAVAILABLE` — a real
Redfish WARNING/CRITICAL was never recorded as its own finding.
Fix: `add(..., snippet="")` forwarding to `issue(...)` (already had the param).
Backward compatible (all callers use keyword args or stop at `detail`).

### P1-2 — malformed referenced entry could false PASS
Root cause: `_redfish_json` returned `{}` on decode failure, and the reference
branch only checked `isinstance(target, dict)`. A referenced member returning
truncated JSON or an empty `{}` normalised to a blank entry → severity "Other" →
`redfish_verdict` = PASS.
Fix (fail-closed): `_redfish_json` returns `None` on failure; new
`_redfish_valid_entry` requires a dict carrying at least one identity/content key
(`Id` or `Message`); the reference branch rejects anything else as a collection
integrity failure. A valid entry with an unknown/blank severity is still a valid
event (not a failure).
> Note: standalone `f30e235` fixes only the truncated-JSON half; the empty `{}`
> half is fixed here in PA and does **not** exist upstream. Standalone was not
> modified.

### P1-3 — dmesg parser parity
Selective port from standalone `cycle_dmesg.py`:
- AER multi-line grouping (status/mask, `[n] Name` bit lines, TLP Header) with a
  bounded 32-line window; per-event `error_bits`/`error_status`/`error_mask`;
  subtype built from named bits so same-BDF/different-bit events are distinct.
- EDAC: `native_error_count` + `<count>` signature collapse (rising CE count is
  not a new failure) while CE/UE stays a distinct severity.
- NVMe: I/O timeout, timed out, controller down, reset failure, abort/device-not-
  ready timeout.

### P1-4 — regression tests
dmesg: corrected/fatal AER, same-BDF different bit, multi-line grouping, EDAC CE
count change, EDAC UE, NVMe timeout, NVMe reset failure (+ sensor C0/C1 parity).
Redfish: P1-1 warning/critical canonical findings with snippet+evidence and no
REDFISH_UNAVAILABLE; P1-2 truncated JSON / `{}` / missing identity / valid
warning / valid critical / valid OK / one-bad-among-good / unknown severity.
Safety: evidence-persistence failure forbids dispatch; single dispatch;
RESPONSE_LOST not re-sent; identity mismatch raises. (Boot-recovery,
incomplete≠completed/valid, complete-FAIL health FAIL, NIC PRESENT→DEGRADED=FAIL,
NIC DEGRADED→PRESENT=recovery, PCI collection failure, rejected≠valid_cycle are
already covered by existing suites, re-run green.)
