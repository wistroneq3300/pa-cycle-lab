## User flow

### Local surface contract

This is an Operate surface extending the existing Wistron shell, typography and
button primitives. Telemetry styles stay scoped to its panel; console content
scrolls locally and controls wrap at the supported desktop widths. Existing
charts, six system tabs and system operations retain their original owners.
No global theme, design tokens or Cycle workspace are replaced.

Open a system → **Telemetry** → select the canonical Node → **啟用 Telemetry**.
The existing charts remain below the new panel. Enabling is optional and never
runs from enrollment, hostname probing, or system creation.

The background job verifies SSH/canonical identity through the existing shared
collector and Identity Auto Sync. A normal hostname rename can proceed; an
identity requiring confirmation stops this job. It checks the exporter, systemd
service, version and listening port before choosing an action:

| Observation | Behavior |
|---|---|
| Healthy existing Node Exporter | Keep it; register/verify monitoring only |
| Recognized service exists but stopped | Start that service; no reinstall |
| No binary/service, Ubuntu or Debian with systemd | Install distribution `prometheus-node-exporter`; enable/start its service |
| Port occupied without valid Node Exporter metrics | ERROR with listener information; do not stop the process |
| Existing binary without recognized service | Preserve files; report the missing service configuration |
| Other OS or custom-port new installation | Explain unsupported automatic installation; existing healthy exporters remain usable |
| SSH or shared identity unavailable | UNREACHABLE / ERROR; no installation |

Automatic installation uses the configured distribution repositories; it does
not download an arbitrary installer URL. It requires root or the existing PA
sudo support, package repository connectivity and systemd. Linux installation
has **not** been executed on real hardware in this delivery.

READY requires a responding Node Exporter, exactly one matching Prometheus UP
target, and fresh samples for exporter build, CPU, memory, filesystem and network.
`timestamp(metric)` checks source-sample freshness, rather than query time.
Prometheus DOWN/missing/stale metrics become DEGRADED. Old READY cache results are
not presented as current READY. GPU collection remains the existing PA facility;
this does not install DCGM or pretend Node Exporter supplies GPU metrics.

## Configuration after review

No central service is installed, restarted or reconfigured automatically.
Port 3000 is never used by this integration. The following are settings for a
future authorized deployment, not changes made by this task:

```text
PA_PROMETHEUS_URL=http://<monitoring-host>:9090
PA_PROMETHEUS_FILE_SD=/etc/prometheus/targets/pa-nodes.json
PA_GRAFANA_URL=http://<browser-reachable-monitoring-host>:3100
PA_GRAFANA_DASHBOARD_UID=pa-node-telemetry
PA_NODE_EXPORTER_PORT=9100
PA_TELEMETRY_VERIFY_SECONDS=90
```

Use the actual existing file_sd path. The PA service account needs permission to
atomically replace that file in its directory. PA is its single writer; unrelated
entries are retained. An existing POC endpoint without another node's identity
is adopted without duplicate scraping, preserving labels and other group members.
An endpoint explicitly belonging to another canonical node is not overwritten.
File_sd registration does not call Prometheus reload or restart.

The existing Prometheus scrape configuration must already reference the file
and preserve `node_id` and `pa_binding` target labels. PA does not edit that
configuration. Confirm the actual setup before use. See the official
[file_sd guide](https://prometheus.io/docs/guides/file-sd/) and
[HTTP API](https://prometheus.io/docs/prometheus/latest/querying/api/).

Import `deploy/telemetry/pa-node-telemetry.json` into the existing Grafana instance,
choosing its existing Prometheus datasource. Alternatively configure a compatible
dashboard UID accepting `var-node_id`. URLs are generated by the server; frontend
code has no hardcoded monitoring host. The supplied dashboard covers CPU, memory,
filesystem and receive throughput by stable node ID.

Grafana login, iframe embedding, browser-reachable URL and HTTPS/mixed-content
settings require confirmation against the installed Grafana. No anonymous access
or authentication changes are made here. The UI also provides a normal Grafana
link. See [URL variables](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/create-dashboard-url-variables/)
and [embedding configuration](https://grafana.com/docs/grafana/latest/setup-grafana/configure-grafana/).

## Ownership and persistence

| Responsibility | File |
|---|---|
| Canonical resolution, existing authorization, HTTP API | `integration/telemetry_routes.py` |
| Durable jobs, request aliases, events, cached health | `integration/telemetry_store.py` |
| Two-worker provision scheduler and explicit installer steps | `integration/telemetry_provision.py` |
| Bounded HTTP reads, Prometheus validation, atomic file_sd, dashboard URLs | `integration/telemetry_monitoring.py` |
| Existing identity reads / metadata sync | `validation_identity.py` / `integration/identity_sync.py` (unchanged) |
| Scoped view/readonly console | `app/static/js/telemetry-provision.js`, `app/static/css/telemetry-provision.css` |
| Synthetic-only transport | `integration/telemetry_fixture.py` |

`<CYCLE_INSTANCE>/telemetry-provision.sqlite3` is separate from Cycle jobs and
the existing telemetry metrics DB. No existing schema is migrated. Jobs use
stable node/chassis IDs; secrets are obtained at execution time, not saved in
the job. Concurrent enable requests join the same active job. Every request key
is remembered, including keys coalesced while another request was running.

The dedicated provision thread pool belongs to the existing single Web process.
It is independent of browser, Console and Cycle workers. **It does not survive
Web process death.** Startup marks in-flight work INTERRUPTED and retains its
events. It does not replay installation. Explicitly enabling again re-detects the
existing installation. Never-dispatched QUEUED jobs can start after restart.
Graceful shutdown stops admission and waits for the current bounded SSH call;
it does not kill a remote package manager. An SSH timeout/lost response may leave
a package operation continuing remotely; an explicit retry must still inspect
the system/package-manager state and will not stop that process.

The existing Web process lock supplies single-owner coordination. No new locks
are applied to Cycle, Terminal, KVM, Inspection or manual power operations.
Network IO runs outside SQLite write transactions. Step intent is committed
before each mutation. Evidence failure prevents that step from being dispatched.

Console events are English, rendered as text, and masked before persistence.
Raw remote failure evidence retains its original content/language after masking.
Time is stored as epoch seconds and displayed/downloaded in UTC+8. Event reads
use `after_seq`, at most 500 per response. Browser rendering is capped at 2,000
rows; downloads stream all saved rows. Pausing freezes the displayed snapshot,
including Copy; switching nodes clears the prior log immediately. Parent view
refresh preserves node selection and paused reading state. No shell input exists.

While provision runs, status polling is 1.5 seconds; otherwise 15 seconds.
Monitoring-only health refresh is coalesced to at most once per Node per 30
seconds, shares the two-worker cap, and never installs software. Closing the
Console stops its event reads; leaving the view disposes UI timers/requests.

Job/event retention is currently explicit: no automatic pruning. Provision logs
are short and each message is bounded; operators should archive the separate DB
under their normal backup policy. This feature does not delete evidence.

## API additions

* `GET /api/telemetry/systems/{name}/nodes`
* `GET /api/telemetry/nodes/{node_id}`
* `POST /api/telemetry/nodes/{node_id}/enable`
  with `idempotency_key` and `expected_binding_revision`
* `GET /api/telemetry/jobs/{job_id}`
* `GET /api/telemetry/jobs/{job_id}/events?after_seq=N&limit=250`
* `GET /api/telemetry/jobs/{job_id}/log`

All use the current PA provider semantics. Project-only operators need no new
global privilege. Historical jobs retain their original project scope and also
check the current project if the node was moved. Existing APIs/payloads are unchanged.

## Isolated demonstration

From this worktree, use a **new** instance name and free loopback port:

```powershell
$env:CYCLE_MODE='synthetic'
$env:CYCLE_INSTANCE='data/telemetry-preview-unique-name'
$env:PA_PREVIEW_URL='http://127.0.0.1:19486'
.venv/Scripts/python.exe -m uvicorn scripts.telemetry_preview:create_app --factory --host 127.0.0.1 --port 19486
```

Open `http://127.0.0.1:19486/`, select `chassis-01`, then Telemetry. This harness
has four canonical nodes. Its test-only fixture routes change raw transport
outcomes; the real production frontend, routes, job store and service execute.
Paramiko hardware connections are rejected. The Grafana frame is explicitly a
local fixture, not a real Grafana server. The harness never starts the normal
hardware collectors. Do not point its data directory at an existing instance.

## Disable / rollback

Until enabled by a user there is no provision job and no DUT installation.
Leaving central endpoints unconfigured disables only the new enable action.
Reverting this delivery commit removes the new API/UI integration; it leaves
Cycle, Inspection and existing metrics untouched. Keep the separate provision DB
for audit. Reverting code does not uninstall an exporter or remove monitoring
targets installed during a future authorized deployment; manage those explicitly.
This delivery installed none.
